Commercial Vehicle Model Update

The Commercial Vehicle Model (CVM) generates daily Light (LT), Medium (MD), and Heavy (HV) commercial-vehicle trips for six vocations – Door-to-Door (D2D), Hub-and-Spoke (HnS), Local (Lcl), Regional (Reg), Long-Haul (LHl), and Unknown (Unk) – from trip-rate models built on LOCUS commercial-vehicle data. Those raw rates rarely match observed commercial-vehicle activity exactly, so a set of calibration factors are layered on top, by county and (for MD/HV) by vocation. This page breaks down, for the selected calibration run, how much of the region’s final commercial-vehicle trips and VMT trace back to the raw LOCUS-based rates (“base model”) versus how much comes from that calibration adjustment – and separately explains what falls outside the CVM entirely: the external (X) end of any trip that crosses the region boundary.

About the LOCUS Data

UDOT has licensed commercial-vehicle origin-destination (OD) data from LOCUS that was geo-referenced to the region’s TAZs and external stations, made available to WFRC as part of a 2025 Wasatch Front TDM Truck Model Update effort. That project used the licensed LOCUS OD data, alongside segment-level roadway volumes with medium- and heavy-duty commercial-vehicle percentages and a base- and horizon-year commercial-vehicle trip table extracted from the Utah Statewide Travel Demand Model (USTM), to re-estimate and calibrate the CVM’s internal (II) trip generation and distribution parameters against 2023 base-year observed commercial-vehicle activity. Per the LOCUS-derived CV TG Rates.csv rate table, that re-estimation also reaches the internal-zone side of IX/XI trip generation (see “Within-region distribution” further down this page). Consistent with the project’s scope, though, USTM continues to supply XX trip tables and the external end zones for IX/XI trips; LOCUS data doesn’t reach those.

A note on vehicle-class definitions. LOCUS classifies commercial vehicles by gross vehicle weight, while UDOT’s roadway count data – including the Continuous Count Station (CCS) adjustments described below – classifies by vehicle configuration: single-unit (SU) vs. multi-unit (MU). The two schemes don’t always agree. A short, rigid single-unit vehicle like a dump truck or concrete mixer can carry a gross vehicle weight well into LOCUS’s “Heavy” bucket while still counting as UDOT’s shorter single-unit (“Medium”) category at a count station. Vehicles like these are a possible source of any mismatch between the CVM’s LOCUS-derived Medium/Heavy split and UDOT’s own Medium/Heavy percentages.

Total Commercial Vehicle Activity

Trips and VMT below cover all commercial-vehicle movement – internal (II), plus any trip with one or both ends outside the region (IX/XI/XX). Each card splits that total into what the raw model would have produced on its own (“base model”) versus the net effect of every calibration factor applied on top (“adjustment”) – a negative adjustment means calibration is scaling the raw estimate down, not up.

function headlineCard(veh) {
  const vehRows = rows.filter(d => d.vehicle_type === veh);
  function totals(metric) {
    const m = vehRows.filter(d => d.metric === metric);
    const factored = d3.sum(m, d => d.factored);
    const unfactored = d3.sum(m, d => d.unfactored);
    return { factored, unfactored, modelPct: factored ? unfactored / factored * 100 : 0, adjPct: factored ? (factored - unfactored) / factored * 100 : 0 };
  }
  const trips = totals("trips");
  const vmt = totals("vmt");

  const row = (label, t) => html`<div style="display:flex; justify-content:space-between; padding:3px 0;">
    <span style="color:${themeNeutral};">${label}</span>
    <span><strong>${fmtInt(t.factored)}</strong> &nbsp;<span style="color:${themeNeutral}; font-size:0.9em;">(${fmtPct(t.modelPct)}% model / ${t.adjPct >= 0 ? "+" : ""}${fmtPct(t.adjPct)}% adj)</span></span>
  </div>`;

  return html`<div style="border:1px solid #e0dfdd; border-radius:8px; padding:14px 18px; flex:1; min-width:240px;">
    <div style="font-weight:600; font-size:1.05em; margin-bottom:6px;">${vehicleLabel.get(veh)}</div>
    ${row("Daily Trips", trips)}
    ${row("Daily VMT", vmt)}
  </div>`;
}

html`<div style="display:flex; gap:16px; flex-wrap:wrap; margin-bottom:12px;">
  ${vehicleOrder.map(headlineCard)}
</div>`

The table below splits that same total into its two sources – internal (II) trips from the CVM rate model versus external (IX/XI/XX) trips from the gateway-station process described further down this page – using each run’s final, fully-calibrated values.

function iiExtTotal(veh, metric) {
  const m = rows.filter(d => d.vehicle_type === veh && d.metric === metric);
  const ii = d3.sum(m.filter(d => vocOrder.includes(d.component)), d => d.factored);
  const ext = d3.sum(m.filter(d => extOrder.includes(d.component)), d => d.factored);
  return { ii, ext, total: ii + ext };
}

Base Model vs. Calibration Adjustment, by Purpose

Each purpose below is one of the six LOCUS-derived vocations, internal (II) trips only – the only place a purpose-specific calibration factor applies (see the section below for IX/XI/XX, which are calibrated by a different, vocation-blind mechanism entirely). The dot marked “Base Model” is what the raw LOCUS trip-rate model alone would produce; “Final (Calibrated)” is this run’s actual output after every calibration factor is applied. The percent label is the calibration factor’s net effect.

What’s Not Part of the CVM: External (X-End) Trips

Not every commercial-vehicle trip touching our region comes from the CVM rate model above. Any trip with an external end – IX (internal origin, external destination), XI (external origin, internal destination), or XX (passing through, both ends external) – has its volume set independently of that rate model, though the CVM’s own data still shapes part of where those trips land:

  • Trip generation: overall AADT at each external gateway station is forecast from HPMS segment AADT volumes, then split into medium- and heavy-duty commercial-vehicle volumes using base-year UDOT medium-/heavy-duty commercial-vehicle percentages – themselves adjusted using revised vehicle-length classifications at nearby Continuous Count Stations (CCS). Not a LOCUS-derived rate model.
  • Within-region distribution (which internal zone originates an IX trip, or receives an XI trip): shaped by the same land-use-based rate table (CV TG Rates.csv, LOCUS-derived) used for internal CVM trips – but for shape only. Those zone-level values are immediately rescaled so the region-wide IX/XI total matches the AADT-derived external total from above, so LOCUS data has no influence on how much IX/XI volume exists, only where within the region it starts or ends.
  • Gateway/route pattern (which external station an IX/XI trip uses, and for XX, which entry-and-exit gateway pair): a separate historical subarea-extraction pattern, not LOCUS/CVM data and not a live run of the Utah Statewide model.

The only calibration applied to these trips is a per-station, per-vehicle-type multiplier (calibFac_Ext_MD_<station> / calibFac_Ext_HV_<station>) that scales a station’s whole commercial-vehicle volume before splitting it into IX/XI/XX shares – there’s no vocation dimension here (LOCUS’s D2D/HnS/Lcl/Reg/LHl/Unk split doesn’t apply), and no LT component at all (Light commercial vehicles are folded into the passenger-vehicle volume at external stations, which get their own separate calibFac_Ext_PL_<station> multiplier). These factors are derived by comparing the resulting link volumes, once forecast, against each station’s CCS Fall 2023 weekday average volume – the difference becomes the adjustment factor, so like the rest of the CVM’s calibration they’re anchored to actual observed station counts rather than a demand-rate model.

Methodology & Caveats

  • Trip generation figures are exact: tdm/2_ModelScripts/2_TripGen/2_TripGen_CV.s multiplies each zone’s raw rate-model production by a county x vehicle-type (x vocation, for MD/HV) calibration factor, in place – so the “base model” value here is the same production divided back out by that factor, not an estimate.
  • VMT figures use an approximation: the calibration factor is unfactored from the origin (production) zone of each trip only. A trip’s destination zone – and, for IX trips, its external end – carries its own factor too, which isn’t undone here. This tends to pull the VMT adjustment slightly toward zero relative to what a full two-sided treatment would show. Treat the VMT split as directionally right, not to the same precision as trip generation.
  • Produced by scripts/cv_purpose_factoring.py (run manually per calibration run; see that script’s module docstring for the full mechanism and scripts/cv_effective_factors.py for the underlying per-zone factor reconstruction).
